Jev．The AI Model That Only Decides

Jev doesn't generate text. It returns typed answers plus calibrated probabilities: pick one option, give a score, or answer yes or no. TypeSafe pitches it as software's "System 1": fast, cheap, and intuitive, built for the flood of small decisions. Real reasoning stays with a regular LLM.
Source: TypeSafe AI launch post ↗ Type: new AI model / early access Compiled: 2026-09-25

TL;DR

Jev turns an LLM from a "chatty assistant" into a function that makes decisions. You pass it some state and a set of closed questions, and it returns answers with confidence scores in one pass.

It is non-autoregressive. Instead of producing one token after another, it computes every answer in parallel. The output space is the schema you define, so there are no format errors and nothing to parse. TypeSafe claims 70–500 ms latency and 40–200× the speed of frontier LLMs. Input costs $0.042 per million tokens, and output is free.

★ Every multiplier comes from TypeSafe's own tests. The company admits its own team built the benchmarks and that "some bias could exist." Early access (waitlist) only opened on 2026-09-15, and nothing has been independently verified yet.

Where the name comes from

System One comes from Kahneman's Thinking, Fast and Slow. System 1 is fast, intuitive, and automatic. System 2 is slow, deliberate, and does the reasoning. TypeSafe argues that today's LLMs are all System 2, yet most decisions inside software only need System 1. "Is this email a refund request or a complaint?" "Does this answer break policy?" Neither is worth several seconds of a model that can write essays.

Jev is named after the economist Jevons and his paradox: when efficiency improves, total consumption goes up. TypeSafe's version is that each order-of-magnitude drop in the cost of intelligence opens up an order of magnitude more uses. (This is marketing, not a technical argument.)

How it works

The whole API comes down to three kinds of closed question, and one call can ask several at once:

Question typeReturnsPydantic mapping
Pick oneThe chosen option plus a probability for every option (up to 255 options, per TypeSafe)Enum / Literal
ScoreA score on a scale, which can be fractional because it comes from a continuous probabilityint
Yes / NoA probability from 0 to 1bool
CompoundSeveral questions evaluated in parallelNested BaseModel

The confidence score is what matters. TypeSafe says the probabilities are calibrated: when it says 0.9, it should be right about 90% of the time. That lets you use the score as a gate. High-confidence answers pass automatically, and low-confidence ones go to a person or a bigger model. TypeSafe calls its training method RLCD (Reinforcement Learning for Calibrated Decisions). No paper has been published.

Context limits are 32k tokens per question and 64k per batch, according to the Pydantic and Cloudflare docs.

Minimal examples

Pydantic AI (pip install "pydantic-ai-slim[typesafe]"):

from pydantic_ai import Agent
from pydantic_ai.models.typesafe import TypeSafeModel

model = TypeSafeModel('jev-latest')
agent = Agent(model, output_type=bool, instructions='Is this harmful?')
print(agent.run_sync('Some input text').output)  # True / False

TypeSafe recommends pairing it with FallbackModel, so a regular LLM takes over whenever Jev can't give a good answer.

Cloudflare Workers AI:

const res = await env.AI.run('typesafe/jev', {
  state: 'The user email…',
  questions: { /* pick-one / score / yes-no definitions */ }
})
// res.answers: each answer plus its probability

GPT-6 Astra and Fable 5.1 latency and speed come from Artificial Analysis measurements; prices are the official list prices. I picked these two models because they are the baseline TypeSafe used in its own benchmarks. The estimate counts input cost only. For the two LLMs, output and reasoning tokens would come on top, hence "≥".

Two things to keep in mind when reading this table. First, LLM latency swings widely with the effort setting: GPT-6 Astra takes about 3 s at low and 6 minutes at max, so any "N× faster" claim depends on which setting you compare against. Against low effort, Jev is roughly 6–40× faster, not 200×. Second, the price gap is real. The input price differs by more than 200×, Jev charges nothing for output, and Fable 5.1 at its highest setting spends an extra 47k reasoning tokens per task on average.

TypeSafe lists these caveats itself. Its own model-capabilities team built the benchmark workflows, so "some bias could exist." The baseline is the average of GPT-6 Astra and Fable 5.1. The LLMs also ran behind a wrapper that asks for probabilities, which makes them slower and more expensive.

"Can't hallucinate" just restates the design. If the output is locked to a list of options, the model can't invent one that isn't there, but that doesn't mean it picked the right one. A wrong answer at 0.95 confidence is still wrong.

An engineer's take

✔ No more parse failures, by design
The model doesn't generate output and then check its format. The output space is the schema, so you can drop the retry and JSON-repair layer entirely.
✔ Confidence you can gate on
If the calibration holds up, it's a better fit for automated decisions than an LLM that's confident and often wrong.
✘ All numbers are self-tested
There's no third-party benchmark yet, so treat the multipliers as upper bounds.
✘ Black box, plus lock-in
RLCD has no paper. The three question types are a TypeSafe-only interface, so switching vendors means rewriting your decision layer.
✘ Known weak spots
It's poor at counting, dates, and math. It answers the question you wrote, which isn't always the one you meant. Accuracy drops as context grows, and adversarial input can trip it up.

Outlines / Guidance / InstructorConstrained decoding on top of any LLM. Choose it if you want to avoid lock-in to a new vendor.
Your own BERT-style classifierAlso fast and cheap, but you collect the data, train it, and run it yourself, and you can't define a new task with a one-line prompt. Choose it for a single high-volume task where you want full control of the data and weights.
Diffusion LMsAlso non-autoregressive, but aimed at generating text faster, and still a research project.

Where it fits

TypeSafe and third-party writers agree on a hybrid setup. Jev sits up front and routes requests quickly, and the LLM only handles the ones that really need it.

ScenarioWhat Jev doesFit
Support / ticket routingDetects intent and sends the ticket to the right flowGreat
Moderation, spam detectionViolation yes/no with a confidence score; low-confidence cases go to a humanGreat
Scoring LLM output / guardrailsReplaces an expensive LLM-as-judgeGreat
Bulk labeling (map-reduce)Classifies tens of thousands of papers or reviews one by one; a third-party test labeled 1,018 papers for $0.08Great
"Smart if" inside agentsDecides at each step whether to call a tool and where to go nextGreat
Game NPCs, robots, simulationTactical decisions a few times per second (not the low-level control loop)Worth trying
Summaries, writing, chatNot possible: Jev doesn't generate textNo
Math, dates, countingBoth TypeSafe and third parties call these weak spotsNo
Audited decisions that need reasonsIt returns answers without any reasoningNo

Rule of thumb: Is it a clearly defined question with a limited set of answers? Use Jev. Does it need new text, an explanation, or multi-step reasoning? Use a regular LLM.

Don't think of Jev as a cheaper LLM. Think of it as an intelligent function call. It isn't here to replace LLMs. It takes over the flood of small decisions that LLMs shouldn't be spending time on.

How it compares with other ML approaches

"Take a state, output options with probabilities" isn't a new idea. Below are the five closest approaches. The first three produce actions (the RL family), and the last two produce decisions (the NLP family). What's actually new about Jev is that it does two things at once: the task is defined in one sentence at call time, and the output is a calibrated decision.
