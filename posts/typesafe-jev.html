Jev．只下判斷的 AI 模型

Jev 不生成文字，只回傳有型別的答案＋校準過的機率：從選項裡挑一個、打分數、回答是或否。官方把它定位成軟體的「System 1」——快、便宜、直覺，專門處理大量的小判斷，需要深入推理的事留給一般 LLM。
來源:TypeSafe AI 官方發布文 ↗ 性質:新型 AI 模型 / early access 整理日:2026-09-25

TL;DR

Jev 把 LLM 從「會講話的助理」變成「會判斷的函式」：輸入一段狀態和一組封閉式問題，一次輸出答案和信心分數。

它是非自迴歸模型：不是一個 token 接一個 token 生成，而是一次並行算出所有答案。輸出空間就是你定義的 schema，所以不會有格式錯誤、也不用解析。官方宣稱延遲 70–500ms、比前沿 LLM 快 40–200 倍，輸入每百萬 token $0.042、輸出免費。

★ 所有倍數都是 TypeSafe 自己測的，官方也承認 benchmark 由自家團隊設計、「可能有偏差」。2026-09-15 才開放 early access（候補名單），目前還沒有第三方獨立驗證。

名字從哪來

System One 借自 Kahneman《快思慢想》：System 1 快、直覺、自動，System 2 慢、審慎、會推理。TypeSafe 的主張是：現在的 LLM 都是 System 2，但軟體裡大部分決策其實只需要 System 1——「這封信是退款還是客訴？」「這段回答有沒有違規？」不值得讓一個會寫長文的模型花好幾秒來回答。

Jev 取自經濟學家 Jevons 和 Jevons 悖論：效率提升後，總用量反而會增加。官方的說法是：智能成本每降一個數量級，就會多出一個數量級的新用途。（這是行銷敘事，不是技術論證。）

它怎麼運作

整個 API 就是三種封閉式問題，一次呼叫可以同時問好幾題：

問題型態回傳Pydantic 對應
選一個選中項＋所有選項的機率分布（官方：最多 255 個選項）Enum / Literal
打分數量表分數，可能是非整數（背後是連續機率）int
是 / 否0–1 的機率bool
組合多題一起平行評估巢狀 BaseModel

信心分數是重點。官方說機率是校準過的（說 0.9 就大約九成對），所以可以直接拿來當閘門：高信心自動放行，低信心再交給人或大模型。訓練方法官方稱為 RLCD（Reinforcement Learning for Calibrated Decisions），目前沒有公開論文。

Context 上限：單題 32k、整批 64k tokens（Pydantic / Cloudflare 文件）。

最小範例

Pydantic AI（pip install "pydantic-ai-slim[typesafe]"）：

from pydantic_ai import Agent
from pydantic_ai.models.typesafe import TypeSafeModel

model = TypeSafeModel('jev-latest')
agent = Agent(model, output_type=bool, instructions='Is this harmful?')
print(agent.run_sync('Some input text').output)  # True / False

官方建議搭配 FallbackModel：Jev 答不好就自動退回一般 LLM。

Cloudflare Workers AI：

const res = await env.AI.run('typesafe/jev', {
  state: '使用者的信件內容…',
  questions: { /* 選一個 / 打分數 / 是否 的定義 */ }
})
// res.answers：每題的答案＋機率

目前只開放候補名單，還沒 GA；SLA、長期定價都還不確定。

「不會幻覺」話術——

GPT-6 Astra、Fable 5.1 的延遲與速度取自 Artificial Analysis 實測，價格取自官方定價。選這兩個模型，是因為 TypeSafe 的 benchmark 正是拿它們當比較基準。「試算」只算輸入費用，兩個 LLM 還沒算輸出和推理 token，所以寫「≥」。

看表要注意兩件事。第一，LLM 的延遲差很大，要看 effort 設定：GPT-6 Astra 開 low 大約 3 秒，開 max 要 6 分鐘，所以「快幾倍」要看拿哪一檔來比。拿 low effort 來比，Jev 大約快 6–40 倍，不是 200 倍。第二，價差是實打實的：輸入單價差了兩百多倍，Jev 又不收輸出費，而 Fable 5.1 最高設定每個任務平均要多花 4.7 萬個推理 token。

官方自己寫出的限制：benchmark 的 workflow 由自家模型能力團隊設計、「可能有偏差」；比較對象是 GPT-6 Astra 與 Fable 5.1 的平均；LLM 那邊還加了一層要求輸出機率的 wrapper，會讓 LLM 變得更慢、更貴。

「不會幻覺」其實是換句話說：輸出被鎖在選項裡，當然不會編出不存在的選項，但這不代表選對了。一個信心 0.95 的錯誤判斷還是錯的。

工程師觀點

✔ 從架構上根除解析失敗
不是生成完再驗證格式，而是輸出空間本身就是 schema，重試、修 JSON 這層可以直接拿掉。
✔ 信心分數可以當閘門
如果真的校準得好，比一般 LLM「很有自信但常錯」更適合用在自動化決策。
✘ 數字全是自測
目前沒有第三方 benchmark，倍數只能當成上限看。
✘ 黑箱＋綁定
RLCD 沒有論文；三種問題的介面是 TypeSafe 專有的，換供應商得重寫判斷層。
✘ 已知弱點
計數、日期、數學算不好；它會照字面回答你寫的問題，不一定是你真正想問的；context 越長越不準；面對對抗性輸入比較脆弱。

類似方案怎麼選

方案差別／何時選它
Structured Outputs（OpenAI / Anthropic / Gemini）同樣拿得到型別安全的輸出，但底層仍是自迴歸生成，延遲和成本跟一般 LLM 同一級。已經在用某一家的模型、不想多接一個服務時選它。
Outlines / Guidance / Instructor在任何 LLM 上做受限解碼。不想被新廠商綁住時選它。
自訓 BERT 類分類器一樣又快又便宜，但要自己收資料、訓練、維運，也沒有「用一句話 prompt 就定義新任務」的彈性。任務單一、量大，而且想完全掌控資料和權重時選它。
Diffusion LM同樣走非自迴歸路線，但目標是加快生成文字，還在研究階段。

應用場景

官方和第三方的共識是混合架構：Jev 擺在最前面快速分流，LLM 只處理真正需要它的請求。

場景Jev 在做什麼適合度
客服 / 工單路由判斷意圖，分派給對應流程很適合
內容審核、垃圾偵測是否違規＋信心，低信心再送人工很適合
LLM 輸出評分 / guardrail取代昂貴的 LLM-as-judge很適合
大量資料標籤（map-reduce）幾萬篇論文、評論逐筆分類；第三方實測 1,018 篇 $0.08很適合
Agent 裡的「智能 if」每一步先判斷要不要呼叫工具、下一步往哪走很適合
遊戲 NPC、機器人、模擬幾 Hz 等級的戰術決策（不是底層控制迴路）值得試
摘要、寫作、對話做不到，Jev 不生成文字不適用
計算、日期、計數官方和第三方都說它弱不適用
需要交代理由的稽核決策只給答案，不給推理過程不適用

一句話判斷：這是「選項有限、定義清楚」的封閉式判斷嗎？是 → 用 Jev。需要產生新文字、給解釋或多步推理？→ 用一般 LLM。

跟過往 LLM 的差異

面向過往 LLM（GPT、Claude…）Jev
生成方式自迴歸，逐 token 生成非自迴歸，一次並行算出所有答案
輸出自然語言（或長得像 JSON 的文字）有型別的值＋校準過的機率
格式可靠度要解析、驗證，偶爾失敗要重試輸出空間就是 schema，不會格式錯誤
不確定性常常過度自信，很難拿到可信的機率每個答案都附信心分數，可以直接當閘門
延遲秒級到分鐘級官方宣稱 70–500ms
計價輸入、輸出都收費，輸出最貴只收輸入 $0.042 / 百萬 token，輸出免費
能力範圍通用：寫作、推理、對話、寫程式只做封閉式判斷，不能寫字、不擅長計算
在系統裡的角色System 2：慢想、深度處理System 1：快思、大量小判斷、分流
不要把 Jev 當成更便宜的 LLM，要把它當成一個有智能的函式呼叫。它不是來取代 LLM 的，而是把 LLM 不該做的大量小判斷接過來。

跟其他 ML 機制比

「給一個狀態、輸出選項和機率」這件事並不新。下面挑了五種最像的機制，前三種是做動作的（RL 系），後兩種是做判斷的（NLP 系）。Jev 真正新的地方在於：任務在呼叫時用一句話定義，而且輸出的是校準過的判斷，兩者同時做到。

機制輸入 → 輸出任務何時定義機率代表什麼跟 Jev 最大的差別
傳統 RL
DQN 玩 Atari、Doom、2048		像素 / 盤面 → 動作訓練時；換一款遊戲就要重訓策略偏好單一環境從零試錯學出來，沒有世界知識；但本機微秒級，比 Jev 快得多
Gato
DeepMind 2022		任何東西切成 token → 動作或文字用一段示範當 prompt下一個 token 的機率自迴歸、模仿學習；什麼都做但都普通，是研究成果
VLA
RT-2、OpenVLA、π0		相機畫面＋指令 → 手臂動作一句話指令，但綁定機器人身體不重視校準輸出連續的物理控制（約 50Hz）；Jev 負責決定做什麼，不負責怎麼動
NLI zero-shot 分類器
BART-MNLI、HF zero-shot pipeline		文字＋候選標籤 → 每個標籤的分數呼叫時，給標籤就能用蘊含機率，未校準最接近的前身：同樣一次前向、呼叫時定義選項。差在模型小、世界知識少，只能做分類
Reranker / Reward model
Cohere Rerank、RLHF 獎勵模型		(問題, 文件) → 一個分數訓練時；問題固定是「相不相關」「人類喜不喜歡」相對排序，不是正確率像 Jev 的「打分數」，但只能回答一種問題，分數也不能當成機率
Jev文字 state＋schema → typed value＋機率呼叫時，一句話＋schema官方宣稱校準過—

一句話看懂：Jev 可以看成「NLI zero-shot 分類器換上大模型的世界知識，再用 RL 把機率練準」。如果放到機器人上，它和 VLA 是上下疊的關係，不是互相取代：

Jev（2–5Hz）：「桌上有紅杯和藍杯，使用者要喝水 → 拿藍杯，p=0.91」
   ↓
VLA（~50Hz）：「看著藍杯，把手臂移過去、夾起來」

Gato / VLA / NLI / Reranker 的描述是依公開論文整理的概略比較，細節以各原論文為準。
